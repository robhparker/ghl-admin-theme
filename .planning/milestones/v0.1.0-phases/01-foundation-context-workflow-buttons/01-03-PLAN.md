    **Observers section.** State: `state.watch = { header: null, contact: null }` where an active slot is `{ mount, root, anchor, rootMo, anchorMo }`; `state.renderTimers = { header: null, contact: null }`; `state.mountWaits = { header: null, contact: null }`. One bounded observer set per placement — always exactly two observers, both scoped to the region: `rootMo` observes `root` with `{ childList: true, subtree: true }` (covers the mount being swapped inside the region, its children being wiped, and contact fields appearing later); `anchorMo` observes `anchor` with `{ childList: true, subtree: false }`, where `anchor = root.parentNode` when that is an Element, else `document.body`. Why the anchor: a wholesale replacement of the region (`test/harness.html` "Re-render header" swaps the entire `.hl_header`; `shim.setContact` swaps `.hl_contact-details-header`) is a childList mutation on the region's PARENT — no observer placed on or inside the region can see the region's own removal. The anchor observer is shallow, so it wakes only when a direct child of that parent changes; the script never observes the whole page with subtree. Record this rationale in the JSDoc above `watchMount`. `watchMount(placement, mount)`: if `state.watch[placement]` exists with the same `mount` and its `anchor.isConnected` -> return (already watching); else `unwatchMount(placement)`; `root = adapter.findRegionRoot(placement, mount)`; compute `anchor`; create `rootMo` and `anchorMo` (each `new MutationObserver(records => onMountMutation(placement, records))`), observe as above, store the slot, `log('observer-attached', { placement })`. `unwatchMount(placement)`: if the slot is null -> return; disconnect both observers, null the slot, `log('observer-detached', { placement })`. `isOwnNode(node)`: an Element with `data-ghlc-button-id`, or with class `OWN.groupClass`, or whose `closest(OWN.groupSel)` is non-null, or a text node whose `parentNode` is own; a `data-ghlc-styles` link is own. Note that a removed text node has `parentNode === null`, so under rule (a) below, when `record.target` is own, treat every removed node as own (it was a child of an own node) — otherwise a `setState` label swap on a connected button would schedule one spurious (idempotent) render. `onMountMutation(placement, records)`: a record is **self-inflicted** when EITHER (a) `isOwnNode(record.target)` and every added node is own and every removed node is own (a write inside our own group: `setState` swapping label/message text, reconcile pruning a button), OR (b) `record.removedNodes.length === 0` and every added node is own (our group or stylesheet link being attached to a native parent). If every record in the batch is self-inflicted -> return; otherwise `scheduleRender(placement)`. Consequently a record whose target is NOT own and whose removed nodes include an own node — HighLevel wiping the mount's children or removing our group — always schedules a render, while our own writes never do. That distinction is the loop guard: every write the reconcile performs yields only self-inflicted records, so a render triggered by a native mutation settles after one pass. `scheduleRender(placement)`: `clearTimeout(state.renderTimers[placement]); state.renderTimers[placement] = setTimeout(() => { state.renderTimers[placement] = null; renderPlacement(placement); log('rerender', { placement }); }, 0)`. `applyContext` clears both `renderTimers` too.

    `renderPlacement(placement)` integration: after computing `desired`: if the mount is missing -> `unwatchMount(placement)`, remove any detached group reference, and, if the route expects this placement (`header`: `ctx.locationId` non-null; `contact`: `ctx.contactId` non-null) and `desired.length > 0`, call `waitForMount(placement)`; else `cancelMountWait(placement)`. If the mount exists: `cancelMountWait(placement)`; if `desired.length > 0` -> `watchMount(placement, mount)` (a no-op while the same mount is still watched and its anchor is connected; when a native re-render produced a NEW mount element, this swaps the observer set onto the new root/anchor — the anchor observer's record is what scheduled this render, so the set follows the replacement without any page-wide observer, and the count never grows); else `unwatchMount(placement)` (nothing to protect; agency pages end with zero observers). `renderPlacement` is idempotent (reconcile by id + ctx), so a spurious observer wake-up costs a few queries and no DOM writes. `waitForMount(placement)`: if already waiting -> return; record `startedAt = Date.now()`... use a tick counter instead of wall time so fake timers work: `{ ticks: 0, timer }`; each tick after `MOUNT_WAIT_INTERVAL_MS`: `ticks += 1`; if `ticks * MOUNT_WAIT_INTERVAL_MS > MOUNT_WAIT_MAX_MS` -> `cancelMountWait`, `log('mount-missing', { placement })`, return; else `renderPlacement(placement)` (which cancels the wait itself once the mount is found). `cancelMountWait(placement)`: clearTimeout + null. `applyContext` cancels both waits before `renderAll()` (a new route restarts the wait from zero). This is a bounded, route-scoped retry (max 60 querySelector calls per navigation), not whole-page polling; note this rationale in the JSDoc.
