## Phase Goal

**As a** staff member with a contact record open, **I want to** press one button that triggers the right HighLevel workflow for exactly that contact and location, **so that** the invite goes out once, to the right person, with no stale context and no duplicate sends.

(Transcribed from the ROADMAP Phase 1 `**Goal:**` line, which is in prose form; no content was added.)

<objective>
Build the walking skeleton of the GHL Customizer: one production-quality vertical slice that proves every layer the phase touches, plus the offline harness and stylesheet that let Rob exercise it in a browser.

The slice: `src/ghl-customizer.js` (vanilla IIFE, D-05) reads its config URL from the `data-config` attribute on its own script tag (D-04), fetches and validates the JSON (`schemaVersion` 1, `enabled`), parses the active location and contact from the URL through the single `adapter` object, renders the "Send Invite" contact button on the contact toolbar, and on click POSTs the D-02 payload to the configured Inbound Webhook URL (D-01), moving the button ready -> submitting -> queued ("Workflow triggered") or failed. The whole path runs headlessly in Node through a tiny DOM shim so `node test/run.mjs` is a real end-to-end check, and in a browser through `test/harness.html` (D-12).

Original code only (D-06); `NOTICE.md` already records the reference project.

Purpose: prove the architecture (config -> context -> adapter -> button -> webhook -> state) end-to-end on the executor's best early-context tokens before expanding navigation, observers, header buttons, and verify mode in Plans 02 and 03.
Output: `src/ghl-customizer.js`, `src/ghl-customizer.css`, `config/agency-config.json`, `test/fixtures/config.json`, `test/dom-shim.mjs`, `test/run.mjs`, `test/harness.html`, `package.json`.
