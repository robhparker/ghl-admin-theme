## Planner assumptions (no CONTEXT.md for this phase — each is a recorded decision, cite by ID)

- **A-01 Theme shape (CLR-01).** `agency.theme` and `locations[id].theme` are optional plain objects with the optional keys `primary`, `sidebarBg`, `sidebarText`, `navActive`. Unknown keys are ignored. `validateConfig` gains no new error condition (Phase 2 A-05 leniency): a bad theme value never removes the buttons.
- **A-02 Color grammar (CLR-03).** `parseColor(value)` accepts exactly `#rgb` or `#rrggbb` (hex digits, either case, exact match). Everything else — named colors, `rgb()`/`hsl()`, 4- or 8-digit hex with alpha, whitespace, non-strings — returns null. The value that reaches the DOM is always the parser's normalized lowercase `#rrggbb`, never the raw config string: that is how "no raw string ever reaches stylesheet or style text" is made true by construction (T-03-01). An empty string or `null` means "absent" and is not a diagnostic; any other rejected value is logged `theme-token-ignored` with reason `invalid`.
- **A-03 One resolver (assumption-delta `promote`).** `locationEntry(config, locationId)` is the single own-property lookup (`typeof locationId === 'string'`, `isPlainObject(config.locations)`, `hasOwn`, entry is a plain object) and `resolveBranding` and `resolveButtons` are refactored to call it. `resolveTheme` reads `agency.theme` then the entry's `theme`, key by key from `THEME_TOKENS`, each through `parseColor`; a valid location value overrides the agency value; an absent or invalid location value falls through to the agency value. Agency-level pages (`locationId === null`) resolve to the agency tokens alone.
- **A-04 Contrast rules (CLR-03).** WCAG 2.x: channel linearization `c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ^ 2.4`, luminance `0.2126 R + 0.7152 G + 0.0722 B`, ratio `(L1 + 0.05) / (L2 + 0.05)` with the lighter color on top. After the merge: (1) `sidebarText` without `sidebarBg` is dropped (`unpaired`); (2) `contrastRatio(sidebarBg, sidebarText) < 4.5` replaces `sidebarText` with `pickReadableText(sidebarBg)` — whichever of `#ffffff` / `#101828` contrasts more — and sets `fallback = true`; (3) `navActive` present with `sidebarText` present and `contrastRatio(navActive, sidebarText) < 4.5` drops `navActive` (`contrast`); (4) `primary` present always yields `primaryText = pickReadableText(primary)`. Reference values: black/white = 21; `#777777` on white = 4.48 (fails); `#767676` on white = 4.54 (passes).
- **A-05 Scoped roots (CLR-02).** Tokens are written only via `style.setProperty(name, hex)` / `style.removeProperty(name)` on (a) every `.ghlc-group` the script creates — `--ghlc-primary`, `--ghlc-primary-text`, `--ghlc-focus` (the focus ring follows primary) — and (b) the sidebar element returned by `adapter.findThemeRoot()` — `--ghlc-sidebar-bg`, `--ghlc-sidebar-text`, `--ghlc-nav-active` — which also carries the `data-ghlc-theme` marker listing the applied sidebar tokens. Active nav items returned by `adapter.findNavActive()` carry `data-ghlc-theme="nav-active"`. Never the html or body element, never a style element, never stylesheet text. The stylesheet's new rules select only `[data-ghlc-theme~="…"]`, so with no marker present they match nothing and HighLevel's own rules stand untouched.
- **A-06 Active-nav selector (unverified — confirm live in Plan 03-02's install check).** `#sidebar-v2` is the verified sidebar surface (2026-09-24). The active nav item inside it is NOT verified; the adapter carries an ordered candidate list (`.hl_nav-item--active` from the community guides, Vue Router's `a.router-link-active`, and the standards attribute `[aria-current="page"]`). `adapter.findNavActive()` returns the matches of the first candidate that matches anything, else an empty array — nothing is marked, `verify().theme.navActive` is 0, and the native active state stands (graceful omission). A live correction is a one-line edit to the candidate list.
- **A-07 Render and observer.** `renderTheme(reason)` runs from `renderAll()` after `renderBranding`, from the theme observer's coalesced timer, and from the `theme` mount-wait tick. It is an idempotent reconcile: every group gets `applyGroupTheme`; the sidebar root gets `applySidebarTheme` + `markNavActive` when any sidebar token is present, else `clearSidebarTheme` + `unwatchTheme`. `ensureGroup` calls `applyGroupTheme(group, state.theme.tokens)` on the group it creates so an observer-driven placement re-render never shows a default-colored button. One theme `MutationObserver` instance with two registrations — the root (`childList`, `subtree`, `attributes` filtered to `class` and `aria-current`) and `anchorFor(root)` (`childList`, shallow) — is attached only while a sidebar token is applied (mirrors Phase 2 A-11: native sidebar means zero theme footprint). The script writes only `style` and `data-ghlc-theme` inside the sidebar and adds no nodes there, so every delivered record is HighLevel's; records whose target `isOwnNode` or is the branding mount (`state.branding.native && state.branding.native.el === record.target`, e.g. the `ghlc-logo` class add) are skipped; anything else schedules one coalesced `setTimeout(0)` retheme.
- **A-08 Missing sidebar root.** `theme-root-missing` is logged once per generation (`state.theme.missingGen`); `waitForMount('theme')` runs only when the resolved tokens include a sidebar token (reusing MOUNT_WAIT_INTERVAL_MS / MOUNT_WAIT_MAX_MS; the tick calls `renderTheme('mount-wait')`); groups are still themed. `applyContext` cancels the theme wait and the theme timer alongside the branding ones.
- **A-09 verify().theme.** `{ root, applied, navActive, ignored, fallback }` — booleans, token names, counts. `observers.theme`, `waiting.theme`, `mounts.sidebarNavActive` are added. No hex value appears anywhere in the report or the console; `safe()` would redact one anyway.
- **A-10 Diagnostics cadence.** `theme-applied` is logged when the applied token set or root changes (`state.theme.appliedKey`), not on every idempotent pass; `theme-token-ignored` and `theme-contrast-fallback` are logged once per generation (`state.theme.logGen`).
- **A-11 Section layout.** A tenth marker `// ==== theme ====` sits between `// ==== branding ====` and `// ==== observers ====`; the static gate becomes ten. Color math, DOM writes, and `renderTheme` live in the theme section; the observer functions live in the observers section next to `watchBranding`; `locationEntry`, `parseColor`, and `resolveTheme` live in the config section next to `resolveBranding`. Comments in the theme section must not name HighLevel selectors (the FND-03 gate scans comments) and the section has no `console.` (DLV-04 gate).
- **A-12 Fixture.** `agency.theme` becomes `{ "primary": "#0f766e" }`; `locA.theme` = `{ "primary": "#c2410c", "sidebarBg": "#1f2937", "sidebarText": "#f9fafb", "navActive": "#374151" }` (all valid, pair contrast ≈ 14:1, navActive vs text ≈ 9.9:1); `locB.theme` = `{ "primary": "not-a-color", "sidebarBg": "#ffffff", "sidebarText": "#f5f5f5", "navActive": "#e5e7eb" }` (primary invalid -> agency `#0f766e`; pair ≈ 1.09:1 -> text falls back to `#101828`; navActive vs `#101828` ≈ 14:1 -> kept); `locC` gets no theme (agency primary only). Every existing key stays.
- **A-13 CSS.** Three rules appended, each selecting a `data-ghlc-theme` marker: `[data-ghlc-theme~="sidebar-bg"]` sets `background-color: var(--ghlc-sidebar-bg)`; `[data-ghlc-theme~="sidebar-text"]` and `[data-ghlc-theme~="sidebar-text"] a` set `color: var(--ghlc-sidebar-text)`; `[data-ghlc-theme~="nav-active"]` sets `background-color: var(--ghlc-nav-active)`. No importance overrides (Phase 2 A-10 rule); if the live check shows a HighLevel rule winning, raise specificity by repeating the attribute selector, never by importance. Descendant anchors are the nav links; badges and status spans inside the sidebar keep their own declared colors.
- **A-14 Harness.** The offline sidebar gains a `nav.hx-nav` with anchors carrying `hl_nav-item`, the active one also `hl_nav-item--active` (the adapter's first candidate); the router's `render()` moves the active class between the Dashboard and Contacts anchors by route; `buildSidebar()` recreates the nav; a `#hx-toggle-nav` control moves the active class without navigating (exercises the theme observer); the banner mentions the theme demo (Location A dark sidebar, Location B fallback).
- **A-15 Existing exact assertions.** Adding the theme observer at locA and the new verify fields changes several exact values in Phase 1/2 tests (observer registration counts, `observers`/`waiting`/`mounts` deepEquals, `assertNoFootprint`). Each is updated to its new exact value — never loosened to `>=` (Phase 2 precedent).
