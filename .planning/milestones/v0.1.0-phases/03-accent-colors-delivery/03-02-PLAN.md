## Planner assumptions (no CONTEXT.md for this phase — each is a recorded decision, cite by ID)

- **B-01 Default publish parameters.** Owner `robhparker`, repository `admin-theme` (matches the existing `DEFAULT_CONFIG_URL`), tag `v0.1.0` (matches `VERSION` and `package.json`), public visibility (jsDelivr serves public GitHub repositories only). Task 1 writes the README and sample against these defaults; Task 2 confirms or changes them; Task 3 rewrites every occurrence consistently if changed.
- **B-02 Snippet form (DLV-01, unverified).** HighLevel's Agency Settings -> Company -> Custom JavaScript field form (raw JS vs HTML) was not exercised in the live checks (the script was injected via a shimmed `document.currentScript`). The README leads with the raw-JS loader — an IIFE that creates a `script` element, sets `src` to the pinned script URL, sets the `data-config` attribute to the pinned config URL, sets `defer`, and appends it to `document.head` — because `document.currentScript` is set for dynamically inserted classic scripts, so `data-config` and the automatic `.css` resolution keep working. It also shows the equivalent `<script src=… data-config=… defer></script>` for a field that accepts HTML. The install check records which form HighLevel accepted.
- **B-03 Sample overrides (DLV-02).** Two location entries: Dummy Clinic (`iDPNGKoFsjvf9wUCrk3V`, real and safe for live tests, full theme, `logoUrl` = the repo's `loc-a.svg` on the pinned tag) and `REPLACE_WITH_LOCATION_ID` (`Example Clinic`, logo-only, `loc-b.svg`). `agency.logoUrl` stays `""` so unconfigured locations and agency pages keep the native Park Health Systems logo; `agency.theme.primary` is `#155eef`, the stylesheet's default, so agency defaults are demonstrated without changing the look of unthemed locations. The `helpCenter` header link and the real `sendInvite` webhook trigger stay exactly as committed.
- **B-04 Contrast of the sample theme.** Dummy Clinic pair `#0b3b3a` / `#e6fffa` ≈ 11.8:1; `navActive #115e59` vs text ≈ 7.2:1; `primary #0f766e` gets white text. `resolveTheme(sample, 'iDPNGKoFsjvf9wUCrk3V')` must return `fallback false` and `ignored []` — the sample never exercises the fallback path (that is the fixture's job).
- **B-05 Kill switch and rollback (DLV-01).** Rollback = change only the tag in the HighLevel snippet to the previous version and reload (jsDelivr keeps every tag). Fastest disable = remove or comment out the snippet in HighLevel (takes effect on reload). `enabled: false` is the config-level switch: because the config is served from the same immutable tag, flipping it means committing the change, tagging a new version, and updating the snippet's tag — the README states this plainly rather than pretending the flag is instant.
- **B-06 Webhook URL exposure (D-08).** The committed config carries Rob's real Inbound Webhook trigger URL; the repo's history and the tracked `.planning/` directory carry it too. Making the repo public makes it world-readable — an accepted trade-off per D-08 (rotate the trigger in HighLevel if abused). The README's security section documents rotation: regenerate the trigger URL in the HighLevel workflow, update `config/agency-config.json`, tag, update the snippet. Task 2 surfaces this explicitly; the planner does not decide it.
- **B-07 What gets pushed.** Only tracked files. `docs/GHL_Customizer_PRD_v0_1.docx`, `.gsd/`, and `.planning/state.json` are untracked and stay local unless Rob adds them. `.planning/` (roadmap, requirements, plans, summaries, verification notes with location IDs and the workflow ID) is tracked and becomes public. No LICENSE file exists: a public repo without one is all-rights-reserved by default (same status as the reference project); adding a license is Rob's later choice, not this phase's.
- **B-08 Consistency gate.** One regex extracts `<owner>/<repo>@<tag>` from `DEFAULT_CONFIG_URL`; the `config:` check asserts every sample `logoUrl` uses that slug and tag, and the `readme:` check asserts every `cdn.jsdelivr.net/gh/` URL in the README uses it and that `<tag>` equals `'v' + package.json version`. A renamed repo or a bumped version that misses one file fails the suite.
- **B-09 Publish verification.** jsDelivr can lag a new tag by a few minutes: the verification fetch retries up to 8 times, 15 s apart, before failing. Success = HTTP 200 for the script, stylesheet, config, and both sample logo SVGs; the script body contains `Version 0.1.0`; the config parses with `schemaVersion 1` and `enabled true`.
