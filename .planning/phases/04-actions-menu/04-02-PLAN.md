## Phase Goal

On an Xcelsior contact record, staff open one "Actions" menu in the name row and fire any of four actions by mouse or keyboard, each with its own visible result and cooldown, while every other location and every plain-button config behaves exactly as in v0.1.2.

Plan 04-01 delivered the widget. This plan makes every item behave correctly on its own: its state and result feedback, the 60 s per-item cooldown, the "Not configured" path for the consent items whose URL does not exist yet (D-15), the synthetic-email pre-check (D-16), per-location overrides, scope, and config validation. Plan 04-03 then ships the Xcelsior menu that relies on all of it.

<objective>
Task 1 proves and completes per-item behavior: failed / unconfirmed / network / handler outcomes on the item and on the trigger, the 60 s cooldown keyed by item id (independent per item, surviving a re-render), the D-15 "Not configured" branch in `resolveAction`, stale clicks, and late results after a contact change. Task 2 adds the configuration-driven `requires: { email: 'real' }` rule (D-16) with re-evaluation at render, reconcile, menu open, and click time, then proves overrides (MENU-02), scope, the empty-menu rule (D-02), validation (D-01), `verify().config.menuIds`, and log hygiene.

Purpose: ROADMAP success criteria 3 and 4 become true and automated for any `menus[]` config; ITEM-05, ITEM-06, ITEM-07 mechanics are proven before the shipped config uses them.
Output: updated `src/ghl-customizer.js` (constants, config comment, buttons, verify, boot) and `test/run.mjs`.
</objective>
