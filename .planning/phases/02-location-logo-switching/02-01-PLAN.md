## Planner assumptions (no CONTEXT.md for this phase — each is a recorded decision, cite by ID)

- **A-01 Mount point.** Default mount is the sidebar logo, `#sidebar-v2 img.agency-logo`, verified live on 2026-09-24 (01-CONTEXT.md selector table). `headerLogo` is the config-selectable alternative per BRD-01 ("sidebar or header, selected in adapter config"): the adapter carries `logoMount: 'sidebar'` as the default and `config.agency.logoMount` may override it with `'header'`; any other value falls back to the adapter default. The header selector is narrowed to `.hl_header img.agency-logo` so a header avatar can never be branded; if HighLevel's header logo carries a different class the header mount simply probes false and branding is omitted (graceful degradation).
- **A-02 Agency fallback.** `agency.logoUrl` is empty in the real config, so the agency tier is absent and the "agency logo" fallback IS the native HighLevel logo. Both cases are implemented: an agency tier when `agency.logoUrl` is a safe URL, native otherwise. Native values (`src`, `alt`, `srcset`) are captured per element on first touch and restored verbatim.
- **A-03 Mutate in place.** The native `<img>` is never cloned, wrapped, moved, or replaced; branding writes `src`, `alt`, `referrerpolicy`, the class `ghlc-logo`, and `data-ghlc-logo` on the existing element and removes `srcset` while branded. This makes BRD-02 (click/navigation preserved) and "no duplicate images" true by construction.
- **A-04 Switch sequence.** On every context change the mount is set immediately to the interim tier (agency if configured, else native) and a client logo is applied only after a detached preload fires `load`; the preload result is applied only when `state.generation` and `state.ctx.locationId` still match. URLs that loaded once are remembered for the session (`state.branding.loaded`) so a revisit or a re-render applies instantly with no interim flash; URLs that errored are remembered for the session (`state.branding.failed`) and never retried until reload.
- **A-05 Config leniency.** New keys are optional and additive under `schemaVersion: 1`: `agency.logoUrl`, `agency.logoAlt`, `agency.logoMount`, `locations[id].logoUrl`, `locations[id].logoAlt`, `locations[id].name`. `validateConfig` gains no new error conditions: a wrong-typed or unsafe logo value is ignored by `resolveBranding` (like unknown action types), never a `config-invalid` that would remove the buttons.
- **A-06 Image URL rule.** `isSafeImageUrl(value)` accepts a string that resolves (against `location.href`) to `https:` with no credentials, or to the page's own origin (so the offline harness can reference `./fixtures/logos/*.svg`); it rejects `data:`, `blob:`, `javascript:`, cross-origin `http:`, and parse failures. Values are written to `src` as the raw config string and compared as raw strings.
- **A-07 Alt text chain.** Location tier: `locations[id].logoAlt`, else `locations[id].name`, else `agency.logoAlt`, else the captured native alt. Agency tier: `agency.logoAlt`, else the captured native alt. Native: the captured native alt.
- **A-08 Location resolution.** Reuses `state.ctx.locationId` from the existing route parser; no second parser. Agency-level routes (`locationId === null`) resolve to `[agency]` or `[]` (native).
- **A-09 Section layout.** A ninth section marker `// ==== branding ====` sits between `// ==== buttons ====` and `// ==== observers ====`; the static marker gate is updated to nine. Comments in the new section must not name HighLevel selectors (the FND-03 gate scans comments).
- **A-10 CSS.** One scoped rule, `.ghlc-logo { object-fit: contain; background: transparent; }`, applied only while a non-native tier is showing, so a transparent client PNG is not drawn over a forced background and a mismatched aspect ratio is contained rather than stretched. No importance overrides; if the live check (Plan 02) shows HighLevel's own rule winning, raise specificity by adding the mount's tag to the selector.
