## Phase Goal

v0.2.0 ships to the agency with confidence: the release is versioned, every menu item and refusal path has been proven on a real Xcelsior owner and member, and staff can be put back on v0.1.2 by changing one tag.

This plan builds the publication gate that the push depends on. The repository is public, and a jsDelivr tag is cached forever. So before anything is published, a read-only scan proves that the tracked tree and every unpushed commit are free of secrets and patient identifiers. The tree is then scrubbed of the live-looking Hint patient ids. The history still carries them after this plan; Plan 06-03 rewrites it, and Plan 06-05 refuses to push until `--history` passes (D-02).

Write `harness/prepush-scan.cjs` with a tree mode (six gating checks) and a `--history` mode whose patient-id check gates the exit code. Prove both modes fail-first on the real repository. Then replace the three live-looking Hint patient ids in the tracked tree with same-shape EXAMPLE ids, keeping every suite and harness green. Create no tag, push nothing, and rewrite no history.

Purpose: D-02 and the checker's publication property. No release path may publish a patient id, and the push is gated on a command whose exit code proves it.
Output: two commits on main: the scanner, and the scrub (exact subject, used by Plan 06-03).
</objective>
